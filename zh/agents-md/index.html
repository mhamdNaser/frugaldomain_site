AGENTS.md 生成器

AI 编程助手打开你的仓库时会读取的文件。只需回答它无法自行推断的内容，比如包管理器、测试命令和不能碰的部分，然后按你的工具所需的格式拿到文件。

  • 格式: 同一套答案生成 4 种格式
  • 预设: 4 种技术栈
  • 由助手读取: 每次会话
从预设开始用典型技术栈填充表单，所有内容都可以修改。

助手猜不到的内容

这里填写的所有内容都会进入文件。字段留空则该行不会出现。

项目

技术栈选择项目所用的工具。

命令

填写你实际会输入的那一行，而不是描述。

规则

值得写的规则，是针对已经出过错的情况的规则。

常用规则勾选适用的规则，每条会成为文件中的一行。

另存为 AGENTS.md（仓库根目录）. 大多数编程助手都会读取，包括 Claude Code 和 Cursor。建议先写这个。

52 行 · 1,409 个字符 · 约 376 个 token 每次会话

文件里该写什么

助手光读仓库推断不出来的事实：用哪个包管理器、测试命令到底是什么、哪些目录是生成的、哪个接口的结构不能改。其他内容它自己都能看到。

哪些内容应该省掉

“写干净的代码”“遵循最佳实践”“使用有意义的命名”这类话会占用上下文却改变不了任何事，因为没有哪个助手会故意写烂代码。值得写的规则，是针对已经出过错的情况的规则。

保持简短

这个文件每次会话都会被读取，所以每一行都要反复付费，文件下方的 token 数就是这笔持续的成本。两百行有用的内容胜过一千行含糊其辞的内容，不再成立的规则应当删除，而不是留着误导。

常见问题

AGENTS.md 是什么？
它是放在仓库根目录的 Markdown 文件，告诉 AI 编程助手如何在其中工作：用哪个包管理器、测试命令是什么、哪些目录是生成的、哪些东西不能动。助手在会话开始时读取它，就像新同事阅读贡献指南一样。
AGENTS.md 里该写什么？
只写助手无法从代码推断的内容：包管理器、真实的测试命令、会被覆盖的生成目录，以及不能改变结构的接口。其他内容它自己都能看到。
哪些内容不该写进去？
像“写干净的代码”“遵循最佳实践”这样的通用指令。它们每次会话都消耗 token，却什么也改变不了。值得写的规则，是针对已经真实发生过的错误的规则。
AGENTS.md 和 CLAUDE.md、.cursorrules 是一回事吗？
内容基本相近，区别在于文件名和各工具自己的一些约定。在页面顶部选择你的工具所需的格式，生成器就会按该格式输出，所以无论你需要这四种格式中的哪一种，填写的答案都是同一套。
