Why seeded, not random

A generator that changes on every run cannot be used in a fixture, a test, or a screenshot that has to look the same tomorrow. The seed is a plain string - put it in the test and the rows come back identical.

Why the rows agree with each other

The email is built from the name above it and the city comes from the country you picked. Data where the email has nothing to do with the name still looks fake at a glance, which defeats the point of testing against it.

What this is not

It is not a privacy tool. These rows are invented, which means they are safe to commit - but replacing real customer data with fake data for an export is a different job, and needs the mapping kept somewhere this page never sees.

Frequently asked questions

Why is the data seeded rather than random?
A generator that changes on every run cannot be used in a fixture, a test, or a screenshot that has to look the same tomorrow. The seed is a plain string: put it in the test and the same rows come back every time.
Why do the generated rows agree with each other?
The email is built from the name above it and the city comes from the country you picked. Rows where the email has nothing to do with the name still look fake at a glance, which defeats the point of testing an interface against them.
Can I use this to anonymise real customer data?
No. These rows are invented, which makes them safe to commit, but substituting fake values for real ones in an export is a different job - it needs the mapping kept somewhere, and this page never sees your data at all.
Which formats can I export?
JSON, NDJSON, CSV, SQL insert statements and a TypeScript array, so the rows can go straight into a seed script, a fixture file or a spreadsheet without reshaping.
